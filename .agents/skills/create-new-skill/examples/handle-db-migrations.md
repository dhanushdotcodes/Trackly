# Skill: Managing Database Migrations

## When to Use
Use this skill when:
- Creating a new SQLAlchemy model or updating an existing database model.
- Generating a new Alembic migration script.
- Upgrading the local or testing database schema.

Do NOT use when:
- Merely querying the database or using models without structural changes.
- Writing raw migrations outside Alembic.

---

## Input
- SQLAlchemy models and changes in `server/models/`.
- Connection URLs for the test or local database.

---

## Steps to Execute

1. Update DB models
   - Follow the patterns in existing models to define new columns or tables.
   - Include type hints for all mapped columns.

2. Generate Alembic Migration
   - Run alembic autogenerate command with explicit description.
   - Example: `PYTHONPATH=..:.:$PYTHONPATH uv run alembic revision --autogenerate -m "add user metadata"`

3. Review the autogenerated script
   - Check the migration file in `alembic/versions/` to ensure it captures exactly the desired changes.
   - Ensure the `upgrade` and `downgrade` functions are safe and non-destructive.

4. Execute Migration
   - Run `alembic upgrade head` to apply the migration.
   - Validate that tests continue to pass with the new schema.

---

## Output Format
- New SQLAlchemy model definition or edits.
- Generated migration script in `alembic/versions/`.

---

## Checklist
- [ ] SQLAlchemy models correctly define the new schema
- [ ] Migration revision script generated successfully
- [ ] Upgrade/Downgrade tested locally
- [ ] Lint checks pass without errors
